# Share 媒体文件切换到 OSS 指南

这份文档说明如何把 `sharefrontend` 的卡片封面和卡片附件，从服务器本地存储平滑切换到对象存储。

## 1. 这个开关控制什么

媒体存储开关只影响后续新上传的分享卡片媒体文件：

- 卡片封面图片
- 卡片固定分类槽位里的附件文件

它不会自动迁移历史本地文件。

历史文件会继续按数据库里每条记录自己的存储位置来读取：

- 旧文件如果原来在本地，就继续走本地读取
- 新文件如果写入 OSS，就继续走对象存储读取

这样做的好处是可以灰度切换，也方便回滚。

## 2. 切换前需要先准备什么

在把新上传媒体切到 OSS 之前，先准备好下面几项：

1. 系统管理里已经可用的对象存储配置
2. 至少一个用于封面的命名空间
3. 至少一个用于附件的命名空间
4. 切换期间，后端本地文件卷仍然保留，便于旧文件继续读取
5. 对象存储 Bucket 已配置好 CORS（浏览器直传需要）
6. 后端使用的 RAM 子账号已授予足够权限

当前实现里，“媒体存储模式”不是写在 `config.yaml` 里，而是通过系统管理页面写入数据库配置。

### 2.1 OSS CORS 配置

因为 `object_storage` 模式下浏览器会直接把文件 PUT 到 OSS，所以 Bucket 必须配置 CORS。

阿里云控制台地址模板：

```
https://oss.console.aliyun.com/bucket/oss-<地域>/<bucket-name>/data-security/cors
```

推荐规则：

- 来源：
  - 生产环境：`https://你的域名`
  - 本地测试：`http://localhost:3002`
- 允许 Methods：`GET`、`PUT`、`POST`、`HEAD`
- 允许 Headers：`Content-Type`、`*`
- 暴露 Headers：`ETag`
- 缓存时间：`300`

注意：本地测试时来源必须带协议和端口，例如 `http://localhost:3002`。

### 2.2 RAM 权限配置

后端使用的 RAM 子账号至少需要以下 Action：

- `oss:PutObject`：生成预签名上传 URL
- `oss:GetObject`：读取 / Stat 对象
- `oss:DeleteObject`：删除对象（回滚、替换、删除卡片时需要）
- `oss:ListObjects`：部分管理操作需要

最小 Policy 示例：

```json
{
  "Version": "1",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "oss:PutObject",
        "oss:GetObject",
        "oss:DeleteObject",
        "oss:ListObjects"
      ],
      "Resource": [
        "acs:oss:*:*:baobaobaibucket",
        "acs:oss:*:*:baobaobaibucket/*"
      ]
    }
  ]
}
```

如果你使用 `acs:SourceIp` 条件限制访问来源，请注意：

- 后端请求 OSS 时会带着后端服务器出口 IP
- 本地开发时浏览器直接请求 OSS，会带着本地开发机 IP
- 因此本地测试阶段要么去掉 `acs:SourceIp` 限制，要么把后端服务器 IP 和本地开发机 IP 都加入白名单
- 否则会出现 `403 AccessDenied: You have no right to access this object because of bucket acl` 错误

## 3. 仍然和本地配置有关的项

虽然媒体模式本身不在 YAML 中，但下面这些后端配置仍然有意义：

```yaml
storage:
  default_provider: "local"
  temp_dir: "/tmp/baobaobaivault"
  max_file_size: 10737418240
```

说明：

- `storage.temp_dir`：后端在上传到对象存储前，会先把文件临时落到本地临时目录
- `storage.max_file_size`：后端上传大小限制仍然受它影响
- 如果切换阶段启用了“本地回退读取”，那本地存储卷仍然需要保留

## 4. 推荐切换顺序

推荐按下面顺序在生产环境上线：

1. 先保持现有本地存储部署不变
2. 在 `系统管理 -> 存储配置` 中新增并验证对象存储配置
3. 在 `系统管理 -> 命名空间` 中创建命名空间
4. 打开 `系统管理 -> 媒体存储`
5. 保持“本地回退读取”为开启
6. 把“存储模式”从 `local` 切到 `object_storage`
7. 分别选择：
   - 一个封面命名空间
   - 一个附件命名空间
8. 保存设置
9. 新建几张测试卡片，确认：
   - 封面预览正常
   - 附件下载正常
   - 历史卡片仍然可以打开

## 5. 推荐的命名空间规划

一个比较实用的做法是：

- 封面命名空间：
  - 专门放较小的图片文件
  - 可以配置更严格的大小限制
- 附件命名空间：
  - 专门放卡片分类文件
  - 可以允许更大的单文件大小

你可以选择：

- 同一个 Bucket 下分不同命名空间
- 或者不同存储配置 / 不同 Bucket 分开管理

具体按你的运维习惯来定。

## 6. 当前后端行为

当前这版实现的行为是：

- 新上传文件根据“系统管理 -> 媒体存储”里的开关决定写本地还是写 OSS
- `object_storage` 模式下，封面和附件采用**浏览器直传 OSS**：
  - 后端生成带签名的 PUT URL（presign）返回给前端
  - 浏览器直接把文件 PUT 到 OSS
  - 上传完成后前端调用 complete 接口，后端把对象元数据写入 `objects` / `object_versions`
- `local` 模式下，文件仍然通过后端中转写入服务器本地磁盘
- 历史文件按每条记录自己的存储字段来读取
- 如果开启了本地回退，旧本地文件仍然可以继续服务
- 对外的卡片媒体访问 URL 不变
- 下载和预览仍然由后端负责流式输出（bucket 保持私有）

这意味着你切换到 OSS 后，不需要修改现有分享卡片的访问链接。

## 7. 系统管理页面字段说明

新页面地址是：

- `/system/media-storage`

页面里的字段含义：

- `存储模式`
  - `local`：后续新上传文件继续写本地
  - `object_storage`：后续新上传文件写对象存储
- `本地回退`
  - 迁移阶段建议保持开启
  - 用来保证历史本地文件继续可读
- `封面命名空间`
  - 新上传卡片封面使用的命名空间
- `附件命名空间`
  - 新上传卡片附件使用的命名空间

## 8. 回滚方案

如果你想停止把新媒体写入 OSS：

1. 回到 `系统管理 -> 媒体存储`
2. 把“存储模式”改回 `local`
3. 保存

结果是：

- 后续新上传文件重新写回本地
- 之前已经写到 OSS 的文件仍然可读
- 历史本地文件不受影响

之所以能这样，是因为每个文件自己的存储位置都已经单独记录了。

## 9. 部署注意事项

在“本地 + OSS 混合阶段”，下面几项都不要马上删：

- 后端本地存储卷挂载
- 对象存储配置和密钥
- 媒体存储页里使用到的命名空间

不要在刚切换到 OSS 后立刻移除本地存储卷，原因是：

- 历史本地文件可能还很多
- 回滚时可能还要重新写本地
- 本地回退读取可能还在生效

## 10. 推荐验证清单

开启对象存储模式前，先确认：

- [ ] Bucket CORS 已配置（生产域名 + 本地 `http://localhost:3002`）
- [ ] RAM 子账号已授予 `oss:PutObject`、`oss:GetObject`、`oss:DeleteObject`、`oss:ListObjects`
- [ ] 如果使用 `acs:SourceIp` 限制，本地开发机 IP 已加入白名单

开启对象存储模式后，建议至少验证下面这些动作：

1. 新建一张带封面的卡片
2. 新建一张包含多个附件的卡片包
3. 打开详情页预览封面
4. 下载一个附件
5. 打开一张切换前创建的老卡片
6. 替换一次封面
7. 替换一次附件

这 7 步都正常，第一阶段切换通常就比较稳了。

## 11. 历史文件迁移

当前第一阶段实现还没有自动迁移历史本地文件。

如果后续要做完整迁移，建议单独做一套迁移工具，流程大致是：

1. 扫描旧的本地分享卡片媒体记录
2. 上传到对象存储
3. 回填每条记录的存储字段
4. 验证读链路
5. 分批删除旧本地文件

更安全的做法是把它设计成独立迁移任务，而不是塞进正常上传接口里。
